# AI-Powered WhatsApp Template Creator (Gradio/Streamlit)

> **Goal:** Build a standalone app where a user describes a WhatsApp template in plain language, an AI
> asks clarifying questions, then auto-fills every template field. A live WhatsApp-style preview shows
> on the right, and a **Submit** button at the bottom saves the template as JSON in the same format our
> backend uses (tenant info ignored).

This is fully self-contained — no access to our backend is needed. The only hard contract: the JSON it
produces must match the format below and obey all Meta template rules.

Work through the four phases in order. Each phase has a deliverable.

---

## Phase 1 — Research WhatsApp templates & format requirements

Understand what a WhatsApp template is and the structure it must take.

- Read Meta's official docs on WhatsApp **Message Templates**: the component model
  (HEADER / BODY / FOOTER / BUTTONS) and template **categories**.
- Understand the **component JSON format** — this is what the app must produce:
  - **HEADER** (optional, max 1): `format` ∈ `TEXT | IMAGE | VIDEO | DOCUMENT`. Text headers carry
    `text`; media headers carry `example.header_handle`.
  - **BODY** (required): `text`, plus `example` for variable sample values.
  - **FOOTER** (optional): `text` only.
  - **BUTTONS** (optional): list of `QUICK_REPLY | URL | PHONE_NUMBER | OTP | COPY_CODE`.
  - **CAROUSEL**: 2–10 cards, each card a mini-template (`HEADER`, `BODY`, `BUTTONS`).
- Understand **variables**: positional `{{1}}`, `{{2}}` or named `{{order_id}}`, and how `example`
  values map to them.

**Template types to support (everything we currently support):** Text, Image header, Video header,
Document header, quick-reply / URL / phone / OTP buttons, and **Carousel** (image or video cards).

**Deliverable:** a short write-up + 3–4 example template JSONs (one text-only, one with an image
header + variables + URL button, one carousel) believed to be valid.

### Reference format (the exact JSON shape to target)

```json
{
  "name": "order_confirmation",
  "category": "UTILITY",
  "language": "en_US",
  "components": [
    {"type": "HEADER", "format": "IMAGE", "example": {"header_handle": ["https://.../img.jpg"]}},
    {"type": "BODY", "text": "Hi {{1}}, your order {{2}} is confirmed.",
     "example": {"body_text": [["Navneet", "ORD-5512"]]}},
    {"type": "FOOTER", "text": "Thank you for shopping with us"},
    {"type": "BUTTONS", "buttons": [
      {"type": "URL", "text": "Track Order", "url": "https://track.x.com/{{1}}",
       "example": ["https://track.x.com/ORD-5512"]}
    ]}
  ]
}
```

Top-level field rules:
- `name`: `^[a-z0-9_]+$`, max 512 chars (lowercase letters, digits, underscores only).
- `category`: `MARKETING | UTILITY | AUTHENTICATION`.
- `language`: one of the 14 codes in Phase 2.

## Phase 2 — Study the Meta rules a template must satisfy

Build a validator that checks a template before "submitting" it. These are the exact rules our
production service enforces:

- **Variables:** `{{1}}` positional OR `{{lowercase_named}}`. No spaces/special chars (`{{$x}}`,
  `{{order#}}` are invalid). No mismatched braces. Named variables are always **lowercased**, and the
  matching `example` param name must match.
- **Body (required):** ≤ 1024 chars; not empty; not 100% variables; **must not start or end with a
  variable**; positional vars sequential from `{{1}}` (no `{{0}}`, gaps, or duplicates); no mixing
  positional + named.
- **Header:** max 1. TEXT ≤ 60 chars and ≤ 1 variable. IMAGE/VIDEO/DOCUMENT use `example.header_handle`.
  AUTHENTICATION templates cannot have media headers.
- **Footer:** ≤ 60 chars, **no variables**.
- **Buttons:** ≤ 10 total. QUICK_REPLY text ≤ 25. URL ≤ 2 buttons, URL ≤ 2000 chars, ≤ 1 variable
  placed **at the end** of the URL. PHONE_NUMBER ≤ 1 (value ≤ 20 chars). OTP/COPY_CODE ≤ 1.
- **AUTHENTICATION category:** no URL buttons; no emojis; OTP body is auto-generated by Meta.
- **Carousel:** 2–10 cards; no top-level buttons; every card has an IMAGE/VIDEO header (same media
  type across all cards); body ≤ 160 chars; 1–2 buttons per card (QUICK_REPLY/URL/PHONE_NUMBER, same
  layout on every card); no footer; card body needs ≥ `2x+1` words for `x` variables.
- **Spam (reject):** > 60% uppercase letters; 5+ repeated `!`/`?`; 6+ consecutive emojis.
- **Sensitive data (reject):** 16-digit card numbers, 12-digit IDs, the word `password`, `ssn`.

### Supported languages (exactly these 14 codes)

`hi, bn_IN, gu, kn, ml, mr, pa, ta, te, ur, en, en_IN, en_US, en_GB`

The AI may write template **content** in any of these languages (e.g. Hindi or Tamil body text), but
`language` must be one of these codes. If the user asks for an unsupported language, the AI should say
so and offer the closest supported option.

**Deliverable:** a `validator` module that takes the component JSON and returns pass/fail + reasons,
covering all the rules above.

## Phase 3 — Plan the Gradio / Streamlit app

Design before coding. Layout and flow:

```
+-------------------------------------------------------------+
|  [ Chat / prompt box ]            |   LIVE PREVIEW           |
|  user: "send order confirmation   |   +-----------------+    |
|         with a tracking link"     |   | [image header]  |    |
|  ai:   "What language? Should I   |   | Hi Navneet,     |    |
|         add a tracking button?"   |   | your order ...  |    |
|                                   |   | Thank you ...   |    |
|  [ Auto-filled fields ]           |   | [Track Order]   |    |
|   name:     order_confirmation    |   +-----------------+    |
|   category: UTILITY               |                          |
|   language: en_US                 |                          |
|   header:   IMAGE [upload]        |                          |
|   body:     Hi {{1}}, ...         |                          |
|   buttons:  URL "Track Order"     |                          |
|-------------------------------------------------------------|
|                   [ SUBMIT ]  -> saves JSON                  |
+-------------------------------------------------------------+
```

Flow:
1. User types a prompt in the chat box.
2. The AI interprets it and **asks follow-up questions** only when something needed to build a valid
   template is missing (category, language, which values are variables, sample values, header/buttons,
   image, etc.). Batch questions where possible — don't over-ask.
3. Once it understands, the AI **fills in all the form fields** on the left (name, category, language,
   header type + media, body with `{{n}}` variables + sample values, footer, buttons).
4. The **right pane renders a live WhatsApp-style preview** that updates as fields populate —
   substituting `example` sample values for variables, showing the uploaded image/video thumbnail for
   media headers, and rendering each button.
5. The fields are **editable** by the user; the preview reflects edits.
6. **Submit button** at the bottom: runs the Phase-2 validator, and on pass **saves the template as
   JSON** to a file (e.g. `output/<name>_<lang>.json`) in our exact format (no tenant info).

Decisions to make and document:
- LLM provider (Claude / Gemini / OpenAI; recommend tool-use / JSON mode so the model returns
  structured fields, not prose).
- A **system prompt** that embeds the Phase-2 rules + 14 languages so the model generates compliant
  output and knows when to ask follow-up questions.
- Conversation state: keep it simple (Streamlit `session_state` / Gradio `State`).
- Image/video handling: user uploads a file; show it in the preview; in the saved JSON put the
  URL/handle under `example.header_handle: [...]`.

**Deliverable:** a 1-page design doc (layout, components, LLM choice, prompt outline, save format).

## Phase 4 — Build the app

Implement the Phase-3 design:
- Gradio or Streamlit app with the chat-left / preview-right / submit-bottom layout.
- AI conversation loop with follow-up questions and auto-fill.
- All template types: text, image, video, document, button variants, carousel.
- Language support across the 14 codes.
- Live preview with media + variable substitution.
- Submit → validate → save JSON in our format.

2. "A marketing message for a Diwali sale — 30% off, with a banner image and a Shop Now link."
3. "OTP verification message with a 6-digit code." *(AUTHENTICATION)*
4. "Appointment reminder with date and time, and a Reschedule button and a Call Us button."
5. "Welcome message for new users in Hindi." *(non-English body)*

7. "A product carousel showing 3 products, each with an image, a one-line description, and a Buy button."

9. "Feedback request after delivery with two quick-reply buttons: Good and Bad."
10. "Flight booking confirmation with PNR, passenger name, and a video header."

## Acceptance criteria

- For the sample prompts above, the app asks sensible follow-ups, auto-fills fields, shows a correct
  preview, and on submit writes JSON that **passes the Phase-2 validator**.
- Coverage across: MARKETING / UTILITY / AUTHENTICATION; named + positional variables; an image
  header; a video or carousel; at least one non-English (e.g. Hindi) body.
- Invalid attempts (body ending in a variable, emoji in AUTH template, 11 buttons, unsupported
  language) are caught — corrected or surfaced, never silently saved.
- Saved JSON matches the Phase 1 format (tenant fields omitted).
